Enable HDR Canvas

This tool uses the rec2100-pq HDR canvas API to render colors beyond sRGB. It requires a Chrome flag to be enabled.

Copy this into Chrome's address bar and press Enter:

chrome://flags/#enable-experimental-web-platform-features

Set it to Enabled, then restart the browser.

Without this flag, tiles fall back to CSS oklch() which cannot exceed SDR brightness.

2 / 7

Display Profile

For accurate HDR color rendering, macOS should use a colorimetric reference profile instead of its default perceptual gamut mapping.

System Settings → Displays → choose HDR Video (P3-ST 2084) as the display preset.

This tells macOS to hard-clip out-of-gamut colors instead of smoothly compressing them, giving you accurate rendering within your display's gamut.

3 / 7

Presets

The presets load CIE Lab measurements of Pantone colors into the OKLCH sliders. There are two illuminant groups:

D50 (no UV) — Standard Pantone measurement light. Fluorescent pigments look like ordinary inks, so the Lab values understate their true vividness.

D65 (with UV) — Daylight including UV. Fluorescent pigments absorb UV and re-emit visible light, producing the neon glow. These independently measured values capture what your eyes actually see.

Selecting a preset converts CIE Lab to OKLCH and sets all four sliders. You can fine-tune from there.

4 / 7

Gamut Boundary Markers

The chroma slider shows where each color space's gamut ends at the current lightness and hue. The slider scales to the CIE 1931 spectral locus — the absolute physical limit of visible color.

sRGB — standard web colors
P3 — wide-gamut displays (iPhone, Mac)
Rec.2020 — ultra-wide gamut (HDR video standard)

Each tile clamps chroma to its gamut boundary. Pushing chroma past sRGB only affects the P3 and Rec.2100 tiles.

5 / 7

HDR Brightness

The HDR brightness slider is not part of the color itself — it controls how bright the Rec.2100 tile is rendered, independently of its hue and saturation.

Most displays capable of P3 or wider gamut also support per-area brightness control — this is what HDR actually is. Rather than a single fixed backlight level, HDR displays (MiniLED local dimming, OLED per-pixel) can push individual regions far beyond the standard SDR white point of 203 nits.

Presets default to 2.0x (406 nits) to showcase what wide-gamut + HDR brightness can do together. Loading from a hex code defaults to 1.0x (SDR) since hex is an sRGB value with no HDR intent.

The combination of wider gamut (more saturated) and higher brightness is what makes HDR content look so vivid compared to SDR — Rec.2100 pairs the Rec.2020 color primaries with the PQ brightness curve, covering both dimensions.

6 / 7

Display Technology Estimates

Dotted markers show where real displays fall between P3 and Rec.2020, estimated from published primary measurements (rtings.com, HDTVTest). These shift with hue:

MiniLED — MacBook Pro, KSF phosphor backlight. Close to P3 at most hues.
QD-OLED — Samsung/Alienware. Extends furthest in red/green (~632nm/530nm QDs), barely exceeds P3 in blue.

Why do I see changes past my display's marker? macOS does not hard-clip out-of-gamut HDR colors. Its EDR pipeline applies perceptual gamut mapping, so you see the Rec.2100 tile keep changing past the dotted line — but those differences are inaccurate. Colors within the marker are rendered accurately; colors beyond are the OS's best-effort approximation. Using the HDR Video reference profile (step 2) reduces this effect.

7 / 7

Verify Your Setup

Before using this tool, confirm that your browser and display are actually rendering HDR content correctly.

Open testufo.com/hdr and look for the WCG HDR test pattern. It should be visibly blinking — alternating between bright HDR colors and standard SDR.

If you cannot see the WCG HDR test blinking, your setup is not properly configured. Go back to steps 1 and 2 and make sure both the Chrome flag is enabled and the correct display profile is selected.

The testufo HDR test uses the same rec2100-pq canvas API as this tool. If it works there, it will work here.
